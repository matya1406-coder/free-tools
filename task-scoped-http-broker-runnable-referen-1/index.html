A concrete starting scope

Restrict operations

A broker-owned allowlist maps permitted operations to fixed HTTP destinations. The agent cannot choose arbitrary URLs or edit the policy.

Limit every task

Short-lived broker tokens grant selected operations and share a persistent task call budget. Failed upstream attempts consume budget too.

Keep keys separate

The broker adds service credentials. The agent receives a restricted task token, not the upstream service key.

Clear limits

This is an initial implementation for evaluation, not a security certification or a guarantee against compromise. Network restrictions must be enforced outside the agent, and the broker is a trusted component. Call limits do not by themselves cap spending or the effects of an allowed operation.

Broker permissions do not automatically create provider-native scoped credentials. Those depend on the API. Real deployments need connector-specific response filtering and review of the host, network and secret configuration.
